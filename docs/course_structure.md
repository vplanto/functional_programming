# Структура та організація курсу

Цей документ описує загальну організацію курсу "Функціональне програмування", цільову аудиторію, формат роботи та вимоги до оцінювання. Розклад та аудиторії можуть змінюватись, тому ми фіксуємо тут базові інваріанти.

## Цільова аудиторія

Курс читається як спільний потік для двох спеціальностей:
- **Комп'ютерні науки (122)** — 2 курс.
- **Прикладна математика (113)** — 3 курс.

Ця обставина вимагає від нас тримати баланс між математичною строгістю та практичною інженерією.

## Формат та обсяг курсу

- **Лекційний матеріал:** 16 академічних годин (8 лекцій).
- **Вид підсумкового контролю:** Іспит.

Оскільки аудиторного часу (лекцій) небагато, формат курсу передбачає **інтенсивну самостійну роботу**. Лекції використовуються для розбору найскладніших концепцій, архітектурних патернів та "живого" кодування (live coding), а не для сухого переказування синтаксису.

## Організація занять (Агностик-підхід)

Щоб не залежати від щорічних змін у розкладі, фіксуємо такі правила:

1. **Офіційний розклад є єдиним джерелом істини щодо часу та аудиторії.** 
   - Заняття можуть бути спареними або проводитись раз на тиждень (наприклад, по суботах або у будні).
   - Актуальний час та місце завжди перевіряйте на офіційному ресурсі деканату.
2. **Синхронність:** Незалежно від того, як стоять пари у розкладі, матеріали (лекції, код) публікуються послідовно у цьому репозиторії.
3. **Гібридний формат (за потреби):** Якщо розклад змушує проводити заняття у нетиповий час (наприклад, субота зранку), ми максимально використовуємо цифрові інструменти (записи, спільні чати) для збереження ефективності.

## Тематичний план (8 тижнів / 16 академічних годин)

Курс розраховано рівно на 8 навчальних тижнів. Зважаючи на обмеження у 16 лекційних годин, ми фокусуємось на інженерних інструментах, які дають найбільший практичний ефект для створення розподілених систем:

1. **Лекція 00:** [Перший контакт, академічна доброчесність та ШІ](00_intro_and_ai.md) — межі автономії ШІ, налаштування та інструменти.
2. **Лекція 01:** [Основи ФП, Незмінність (Immutability) та парадокс "копіювання"](01_immutability_and_state.md) — чому shared mutable state вбиває розподілені системи.
3. **Лекція 02:** [Функції як дані: Смерть циклу `for` та анатомія згортки (`fold`)](02_first_class_functions.md) — функції вищого порядку, хвостова рекурсія, паралельні колекції.
4. **Лекція 03:** [Залізничне програмування (Railway-Oriented): Смерть `null` та `Exceptions`](03_railway_oriented_programming.md) — безпека типів, контейнери `Option`, `Either`, `Try`.
5. **Лекція 04:** [Моделювання предметної області: Алгебраїчні типи даних (ADT) та Pattern Matching](04_algebraic_data_types.md) — типи-суми, типи-добутки, Smart Constructors, унеможливлення невалідних станів.
6. **Лекція 05:** [Від синхронного I/O до асинхронності: криза Thread-per-Request та анатомія Future](05_async_futures_and_non_blocking.md) — обчислювальні ефекти, монадичний контекст часу, неблокуючий I/O, `ExecutionContext`.
7. **Лекція 06:** [Реактивні потоки, Backpressure та траблшутинг](06_reactive_streams_and_troubleshooting.md) — Reactive Streams, Project Reactor / Akka Streams, пастки дебагу, контексти.
8. **Лекція 07:** [Фінал: Модель Акторів, патерн Functional Core / Imperative Shell у 23_runner та путівник до іспиту](07_actors_event_sourcing_and_exam.md) — Pekko/Akka актори (концепція для мультиплеєра), чисте ядро vs імперативна оболонка рушія, Event Log, архітектурний підсумок.

### Методичний вибір: Прагматичний монадичний контекст замість абстрактної теорії категорій

* **Чому немає окремих лекцій з абстрактних Typeclasses та чистих IO-монад (Cats Effect / ZIO)?**  
  Формат у 16 академічних годин для студентів 2–3 курсу вимагає жорсткої пріоритизації. Спроба викладати абстрактну теорію категорій (ендофунктори, аплікативні функтори, Kleisli arrows, вільні монади) забирає 3–4 тижні сухої математики, витісняючи прикладні концепції: асинхронний I/O, потоки з backpressure та модель акторів.
* **Як побудовано місток знань про монади та ефекти:**  
  Замість важких зовнішніх бібліотек концепція **обчислювального ефекту (Computational Effect)** розкривається послідовно через стандартні типи-контейнери:
  1. *Ефект відсутності значення:* `Option[T]` (Лекція 03).
  2. *Ефект типізованої доменної помилки:* `Either[E, T]` (Лекція 03 — Railway-Oriented Programming).
  3. *Ефект перехоплення винятків JVM:* `Try[T]` (Лекція 03).
  4. *Ефект затримки у часі та асинхронності (Latency):* `Future[T]` (Лекція 05).
  5. *Ефект нескінченного потоку подій у часі:* `Flux[T]` / `Source[T]` (Лекція 06).
  
  Усі вони підкоряються єдиному закону **монадичного зв'язування (`flatMap` / `for`-comprehension)**: ізолювати нечистий/невизначений контекст і безпечно комбінувати його без мутацій і без виходу з чистого функціонального простору.

## Як успішно здати курс (Іспит)

- **Код — це ваш аргумент.** Оскільки це програмування, на іспиті важливо вміти читати та писати функціональний код.
- **Репозиторії:** Всі практичні завдання та лабораторні (якщо вони передбачені вашим індивідуальним планом) здаються у вигляді посилання на ваш GitHub-репозиторій із виконаним завданням.
- **Розуміння > Заучування.** На іспиті ми будемо говорити про архітектурні рішення, чому ви обрали той чи інший підхід, а не перевіряти пам'ять на назви методів стандартної бібліотеки.
